# ADR-0001 — The commitment is the central object

**Context.** The source of truth (§3) says Forge is management-centric: its object is
the commitment, not the task. Work tools already model tasks well; what is lost is the
line from a decision to an owned promise to an observed outcome.

**Decision.** One object: a commitment — an owner's promise to a principal, of an
intended outcome, by a date, proven by named evidence, answering to an origin. No task,
board, sprint or milestone type exists. Decomposition is a commitment with a parent.
Work stays in the systems that do it and arrives as execution links, activity and
evidence. The principal is explicit: a promise is always made *to* someone, and that
party decides changes to it.

**Consequences.** Forge cannot drift into a project-management tool without adding an
object, which review and `verify:boundaries` would see. Teams keep their trackers.
Every commitment answers the eight questions of §3 from its own record.
